# PYBUS_CONCEPT_001

## Status

Planned.

PYBUS is intended to be a local-first interactive learning app for Python and cybersecurity practice.

The original idea started as a “Python bus” or “learning bus” concept and expanded into a complete hands-on lab environment.

PYBUS should feel like an offline classroom, lab bench, practice-test engine, and local tutor.

---

## Core Purpose

PYBUS helps users learn by doing.

Instead of only reading lessons, users should:

* complete coding exercises
* run commands
* answer quizzes
* practice Security+ style questions
* complete guided labs
* receive local feedback
* track progress
* ask a local LLM tutor for help

---

## Product Identity

PYBUS stands for a learning vehicle.

It should feel like:

```text
a school bus for technical skill-building
```

Tone:

* practical
* encouraging
* structured
* hands-on
* offline-first

Avoid making it childish.

The design can have a playful bus/school concept, but the software should still feel serious enough for portfolio use.

---

## Initial Focus

PYBUS should support two learning tracks:

1. Python fundamentals
2. Security+ / cybersecurity labs

The app can start with Python first, then expand into Security+.

---

## MVP Goal

Build an offline Flask or FastAPI web app with:

* splash screen
* dashboard
* lesson list
* exercise viewer
* code execution area
* quiz/practice-test module
* progress tracking
* optional local LLM tutor panel

No cloud requirement.

No paid APIs.

No user accounts in MVP.

---

## Hands-On Code Execution

MVP should support safe, limited Python execution.

Rules:

* run in a temporary working directory
* timeout every run
* capture stdout/stderr
* block obvious destructive commands where possible
* never run as administrator
* keep execution local

Future sandboxing options:

* subprocess isolation
* Docker optional
* restricted Python runner
* WASM Python optional

Do not overbuild sandboxing in the first MVP, but do not ignore safety.

---

## Security+ Lab Direction

Security+ side should include:

* terminology drills
* scenario-based questions
* command-line labs
* log reading exercises
* network diagram interpretation
* incident response walkthroughs
* Windows security basics
* Linux security basics

Avoid offensive hacking tooling as the main identity.

Position PYBUS as:

```text
defensive cybersecurity learning lab
```

---

## Local LLM Tutor

Future or optional MVP feature:

* Ollama-backed chat panel
* answers questions about current lesson
* explains failed code
* summarizes quiz results
* gives hints instead of full answers by default

Do not make local LLM required.

If Ollama is not running, PYBUS should still work.
