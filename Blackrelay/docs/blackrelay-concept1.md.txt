# BLACKRELAY_CONCEPT_001

## Status

Planned.

BlackRelay is intended to be a local-first workflow automation and routing tool for the Blackfong software ecosystem.

It is separate from BlackBus.

BlackBus moves events.

BlackRelay reacts to events.

---

## Core Purpose

BlackRelay watches for local events and triggers local actions.

Example:

```text
3000 saves a motion snapshot
↓
BlackRelay detects the new event or file
↓
BlackRelay routes it to QuietDrop
↓
BlackRelay creates/logs an alert for Nightwatch
```

---

## Relationship to BlackBus

BlackBus is the event highway.

BlackRelay is the dispatcher.

BlackRelay can work in two modes:

1. Folder watcher mode
2. BlackBus subscriber mode

MVP should start with folder watcher mode because it is simpler.

Later, BlackRelay should subscribe to BlackBus events.

---

## Initial Project Goal

Build a local automation router that can watch folders, detect new files/events, log relay activity, and run dry-run adapters for other Blackfong tools.

No cloud.

No AI.

No required dependency on QuietDrop or Nightwatch yet.

---

## MVP Commands

```bash

```

---

## MVP Behavior

1. Create config file:

```text
blackrelay.toml
```

2. Watch configured folders.

3. Detect new files.

4. Classify basic file event:

```text
snapshot.created
file.created
log.created
```

5. Write relay event to SQLite.

6. Print Rich terminal alert.

7. Route to dry-run adapters:

```text
QuietDrop adapter
Nightwatch adapter
```

8. Do not require those tools to actually exist yet.

## Example Config

```toml
[watch]
paths = ["data/snapshots"]

[routes.snapshot_created]
source = "3000"
match = "*.jpg"
adapters = ["quietdrop", "nightwatch"]

[adapters.quietdrop]
mode = "dry_run"

[adapters.nightwatch]
mode = "dry_run"
```

## What BlackRelay Is Not

BlackRelay is not:

* the event bus
* OBEOS
* DAISE
* a full automation platform yet
* a GUI
* a cloud workflow tool
* Zapier clone with accounts

It is a local workflow dispatcher.

---

## Future Integration

Future BlackRelay should support:

* BlackBus subscription
* real QuietDrop archive action
* real Nightwatch task/log creation
* shell command adapters
* Python function adapters
* retry logic
* failed route queue

## MVP Rules

Do not add:

* AI
* cloud sync
* remote APIs
* authentication
* GUI
* complex rule engine
* dependency on OBEOS

Keep it small and testable.
